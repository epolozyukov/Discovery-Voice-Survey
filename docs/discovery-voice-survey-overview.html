How the pieces fit together

A small web app that collects answers from experts before a Discovery workshop. Experts type or speak; speech is turned into editable text. Questions are fixed by the admin.

Only one AI model: Whisper (speech-to-text) No LLM · no generated questions Audio is never stored
  1. Admin works in the browserSigns in (Supabase Auth checks the password; the app also checks the email is on the admin list), builds surveys and generates links.
  2. Expert opens a personal linkThe server checks the token and the survey status, then loads the questions. Answers are saved as they go.
  3. App ⇄ database, server-side onlyThe browser never talks to the database directly; only the Vercel server code does, with a secret key.
  4. Voice → textRecorded audio goes to the app, then to Groq’s Whisper model, and plain text comes back into the answer box. The expert edits it. Audio is discarded, only the final text is saved.
  5. Automatic deploymentEvery merge to main on GitHub is built and published by Vercel.

Limits of the free voice service (Groq free tier)

Groq’s free-plan caps
  • ≈ 20 transcriptions per minute, shared by all experts
  • ≈ 2,000 transcriptions and ≈ 8 hours of audio per day
  • ≈ 2 hours of audio per hour
What that means in practice
  • Fine for 10–100 experts answering over several days (≈ 45 s per answer)
  • If many record at the same moment (e.g. a live session), some see “We couldn’t transcribe”; they retry after a minute or simply type
  • Typing is never limited
Limits built into the app
  • Max 5 minutes per recording
  • Max 20 recordings per minute per expert link
  • Need more capacity? Move Groq to a paid plan, or host Whisper ourselves; only settings change, not the app
Figures are Groq’s published free-plan limits at the time of writing and may change: check console.groq.com → Settings → Limits.
Tech: Next.js · React · TypeScript · Tailwind · Supabase (PostgreSQL + Auth) · Vercel · Groq Whisper · tested with Vitest + Playwright

How to run a survey

Admin site: https://discovery-voice-survey.vercel.app/admin

You (admin) · about 5 minutes

  1. Sign inOpen the admin site and use your email and password. New admins are added by the project owner.
  2. Create the surveyClick Create survey. Add a title, a short description (shown to experts on the welcome screen) and your questions. Use ↑ ↓ to reorder and untick Required for optional ones.
  3. Save, then ActivateLinks only work while the survey is active.
  4. Generate linksUnder Participants choose how many and click Generate. You get one link per expert (SME-001, SME-002…).
  5. Send each expert their own linkClick Copy link and send it by email or chat. One link per person: it identifies them, so don’t forward one link to several people.
  6. Follow progress and exportThe survey page shows how many are not started / in progress / completed. Click Open to read a response; export CSV or JSON (completed responses only).

The expert · about 8–10 minutes

  1. Open the link and click StartNo account or login needed.
  2. Answer each questionType, or click 🎙 Record Answer, speak, then Stop Recording. The text appears in the box: check it and fix any mistakes. Record Again replaces it. Allow the microphone when the browser asks; typing always works.
  3. Next / BackAnswers are saved as they go and survive a page refresh. Required questions can’t be skipped.
  4. Review and submitCheck all answers, edit any of them, then Submit Interview. After submitting, the link is read-only.
Questions lock after the first answerTo change wording later, reset those experts’ answers first, or create a new survey.
Deactivate stops all linksExperts then see “This survey is not open”. Activate again to reopen.
Reset or delete an expertOpen their response: Reset answers lets them start over on the same link; Delete removes them completely.
Voice and privacyAudio is not stored. It is sent to Groq only to be turned into text; recordings are up to 5 minutes. Only the final text is kept.
Changing an admin passwordSupabase → Authentication → Users: delete the admin and add them again with the new password (same email). No survey data is affected. Ask the project owner.
Trouble with voice? Typing is always available as a fallback. Admins can check the transcription service at /api/transcription/health while signed in.
